요즘 AI 에이전트로 일하면 터미널 창이 금방 늘어납니다. Claude Code를 하나 띄우고, 다른 이슈를 보려고 Codex를 하나 더 띄우고, 빌드 로그를 보려고 터미널을 또 엽니다. 브랜치를 오갈 때마다 작업 중이던 변경을 stash하고 에이전트가 끝났는지 확인하려고 창을 하나씩 눌러 봅니다. 자리를 비우면 에이전트가 질문을 남기고 멈춰 있어도 알 수가 없습니다.

Orca를 쓰고 나서 이 불편이 대부분 사라졌습니다. 아직 써 보지 않았다면 한 번 써 보시라고 권하고 싶어서 몇 주 동안 실제로 쓴 기능 위주로 정리해 봤습니다.

## Orca가 뭔가

[Orca](https://www.onorca.dev)는 Stably AI가 만든 에이전트 개발 환경입니다. 공식 소개 문구도 "The agent development environment"입니다. 코드 편집기라기보다는 여러 AI 에이전트를 한곳에 모아 놓고 돌리는 작업 공간에 가깝습니다.

핵심은 세 가지입니다.

- Claude Code, Codex, Gemini 같은 CLI 에이전트를 하나의 창에서 탭으로 띄웁니다.
- 작업마다 git worktree를 따로 만들어서 에이전트끼리 서로의 변경을 건드리지 않습니다.
- 데스크톱에서 돌던 에이전트를 휴대폰 앱에서 이어서 보고 지시할 수 있습니다.

macOS, Windows, Linux를 지원하고 MIT 라이선스 오픈소스라 무료입니다. 에이전트는 각자 쓰던 구독(Claude, ChatGPT 등)을 그대로 씁니다. 공식 설명으로는 코드와 에이전트 작업이 내 컴퓨터에서 돌아가는 로컬 우선 구조입니다.

## 에이전트를 창 구분 없이 한곳에서

제일 먼저 체감한 건 창 정리입니다. 새 탭 메뉴에서 터미널, 브라우저 탭, Markdown 문서와 함께 Claude, Claude Agent Teams, Codex, Gemini를 바로 고를 수 있습니다.

![Orca 새 탭 메뉴에서 에이전트 선택](/uploads/1792474191000-orca-agent-menu.png)

예전에는 에이전트마다 터미널 앱 창을 따로 열고 이름을 붙여서 구분했습니다. 지금은 프로젝트와 worktree 아래에 탭으로 쌓이고 사이드바에 세션마다 진행 상태와 경과 시간이 표시돼서 어떤 에이전트가 끝났는지 한눈에 보입니다. 같은 문제를 Claude와 Codex에 동시에 맡겨 놓고 답을 비교하는 일도 탭 전환만으로 됩니다.

## 워크트리 분할

Orca에서 작업 단위는 git worktree입니다. 왼쪽 사이드바에 프로젝트가 있고 그 아래에 worktree가 하나씩 붙습니다. 위 스크린샷에서도 같은 저장소 아래에 이슈 브랜치와 `dev` 브랜치가 각각 따로 떠 있습니다.

worktree는 같은 저장소를 폴더만 달리해서 여러 브랜치를 동시에 체크아웃해 두는 git 기능입니다. 원래도 쓸 수 있었지만 폴더를 만들고 지우고 경로를 기억하는 게 번거로워서 손이 잘 안 갔습니다. Orca는 새 작업을 만들면 worktree를 알아서 만들고 사이드바에서 누르면 그 폴더의 터미널과 에이전트로 바로 넘어갑니다.

덕분에 한 이슈를 에이전트가 고치는 동안, 다른 worktree에서 급한 버그를 보는 식으로 일할 수 있게 됐습니다. 브랜치를 바꾸려고 stash할 일이 없고 두 에이전트가 같은 파일을 동시에 고쳐서 꼬이는 일도 없습니다.

## Jira 연결

Jira를 연결하면 Orca 안에서 내 이슈 목록을 볼 수 있습니다. 할당된 이슈를 상태별로 묶어서 보여 주고 목록과 보드 보기를 오갈 수 있고, JQL로 검색도 됩니다.

![Orca 안에서 본 Jira 이슈 목록](/uploads/1792474191000-orca-jira-board.png)

이슈에서 바로 작업 공간을 만들 수 있어서 좋았습니다. 이슈 옆 버튼으로 그 이슈용 worktree를 열면 이슈 키가 그대로 작업 이름이 되고 목록 필터로 이미 작업 공간이 있는 이슈만 골라 볼 수도 있습니다. 어떤 worktree가 어떤 이슈였는지 헷갈릴 일이 없습니다. 브라우저에서 Jira를 열어 이슈를 복사하고 터미널로 돌아와 브랜치를 만들던 왕복이 줄었습니다.

## 모바일 연동

개인적으로 가장 마음에 드는 기능입니다. Orca 모바일 앱(iOS, Android)을 데스크톱과 연결해 두면 휴대폰에서 지금 돌고 있는 worktree와 에이전트 세션을 그대로 볼 수 있습니다.

![Orca 모바일 홈 화면](/uploads/1792474191000-orca-mobile-home.jpeg)

홈 화면에는 연결된 데스크톱과 활성 worktree 수, 이어서 볼 작업, 에이전트별 사용량이 나옵니다. 데스크톱 연결은 QR 코드로 한 번 페어링하면 끝이고 같은 네트워크에 있으면 직접 연결됩니다.

세션을 열면 데스크톱에서 보던 에이전트 대화가 그대로 나오고 아래 입력창으로 메시지를 보낼 수 있습니다.

![모바일에서 에이전트 세션 이어 보기](/uploads/1792474191000-orca-mobile-session.jpeg)

회의에 들어가기 전에 에이전트에게 긴 작업을 맡겨 두고 중간에 휴대폰으로 진행 상황을 확인하다가 질문이 오면 바로 답해 줄 수 있습니다. 예전에는 자리로 돌아와서야 에이전트가 10분 전에 확인을 기다리며 멈춰 있었다는 걸 알았는데, 이제 그런 대기 시간이 거의 없습니다.

## 아쉬운 점

모든 에이전트가 터미널 형식으로 돌아간다는 점입니다. Orca는 에이전트의 CLI를 터미널 탭 안에서 실행하는 구조라, 대화도 결국 터미널 화면입니다. 긴 답변을 스크롤하거나 일부만 골라 복사하기가 채팅형 앱보다 불편하고 표나 코드 블록도 터미널이 그릴 수 있는 만큼만 보입니다. 터미널에 익숙하지 않은 사람에게는 진입 장벽이 될 수 있습니다.

## 마치며

여러 에이전트를 동시에 굴리기 시작하면 에이전트 성능보다 그 작업들을 관리하는 쪽이 먼저 병목이 됩니다. Orca는 그 관리 부분을 꽤 잘 덜어 줍니다. 터미널 위주라는 점만 괜찮다면, 에이전트를 두 개 이상 쓰는 분들께는 충분히 써 볼 만한 도구입니다.
